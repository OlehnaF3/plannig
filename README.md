# Управление планированием (WMS)

Chrome-расширение для управления волнами планирования в WMS-системе

## Возможности

- **Отправить в отбор** — отправка выбранных заказов в отбор с указанием приоритета
- **Перестроить приоритеты** — полное перестроение приоритетов всех запланированных волн
- **Сбросить планирование** — сброс текущих волн (очистка очереди RabbitMQ + скачивание отчёта)
- **Dev Popup** — панель для ручного выполнения операций из popup расширения

## Установка

1. Откройте Chrome и перейдите на `chrome://extensions/`
2. Включите «Режим разработчика» (правый верхний угол)
3. Нажмите «Загрузить распакованное» и укажите корневую папку проекта

## Конфигурация

Все параметры вынесены в `config.js`:

| Параметр | Описание | PROD | TEST |
|----------|----------|------|------|
| `baseUrl` | Адрес WMS-сервера | `*` | `*` |
| `instance` | Имя инстанса | `PROD` | `TEST` |
| `idReport` | ID отчёта для скачивания | `2` | `1` |
| `pickStrategyPolicyId` | ID стратегии отбора | `{ standard: '1', simplified: '2' }` | `{ standard: '1', simplified: '2' }`
| `taskReleasePhases` | Фазы выпуска задач | `['0', '0']` | `['0', '0']`
| `actions` | Действие | `0` | `0`
| `rabbitQueuePrefix` | Префикс очереди RabbitMQ | `ULR` | `ULR` 
| `rabbitQueueSuffix` | Суффикс очереди | `ALLOC` | `ALLOC`

### Создание файла конфигурации

Файл `config.js` не хранится в репозитории (из-за `.gitignore`). Создайте его:

```js
// Скопируйте config.template.js и заполните значения
cp config.template.js config.js
```

## Работа

### Content Script (на странице WMS)

Расширение внедряет три кнопки в футер страницы:

1. **Отправить в отбор** — открывает попап для ввода приоритета, затем отправляет выбранные строки
2. **Перестроить приоритеты** — предлагает выбрать стратегию (Стандарт/Упрощенный) и перестраивает все приоритеты
3. **Сбросить планирование** — сбрасывает текущие волны (требует подтверждения)

### Popup (Dev-панель)

Popup расширения предоставляет кнопку для ручного управления:

- **Purge** — скачивание отчёта + очистка очереди RabbitMQ
- **Rebuild Planning** — полное перестроение планирования

## Безопасность

- Токен авторизации берётся из cookie, localStorage, sessionStorage или meta-тега
- Все запросы используют Bearer-токен из заголовка `Authorization`
- Файл `config.js` исключён из git для предотвращения утечки настроек

## Известные проблемы

- Хардкод ID стратегий в popup стратегии (content.js:534-538)
- Дублирование логики между content.js и popup.js
- Content scripts загружаются как модули (`"type": "module"` в manifest), но не используют ES6-модули

## Разработка

### Добавление новых конфигурационных параметров

1. Добавьте параметр в `config.js` в объект `CONFIGS`
2. Используйте через `API_CONFIG.именПараметра` в content.js и popup.js

### Отладка

- Content Script: нажмите Inspect на странице WMS → вкладка Console
- Popup: нажмите Inspect на странице расширений (`chrome://extensions/`)
